# Structure

## The repo

```
src/                      the React UI
  main.tsx, App.tsx       the entry point and the shell (tabs, polling, toasts, dialogs)
  api.ts                  the commands the UI calls, with their types
  data/                   maps.ts (the map type and list, shared with the extract script) and
                          halloween-maps.json (generated by scripts/extract-game.ts, embedded in the Rust build)
  styles/                 app-wide CSS: the palette and base, the shell, shared controls
  components/             parts shared by the tabs: the tab strip, fields and switches (each with its CSS)
  features/               one folder per tab: contracts/, overlay/, settings/ (views, their parts, their CSS)
scripts/                  maintainer tools: the map list extract
  lib/                    what the extract needs: Valve file formats, the TF2 install lookup, the VTF decoder
public/                   fonts and map screenshots, copied into dist/ by the build
assets/                   icon.svg (the UI favicon) and icon.ico
src-tauri/                the Tauri app: the Rust backend and the window settings
  src/                    the backend, below
  vendor/steam-vent/      a patched copy of the steam-vent crate, see vendor/PATCHES.md
  icons/                  the app icons
docs/                     these docs
```

All CSS is imported in `src/main.tsx`, in one fixed order, since later files win ties.

## The backend

```
src-tauri/src/
  main.rs                 the window, the tray and startup
  commands/               what the UI calls: mod.rs (state, queue, settings, Steam), overlay.rs (the Overlay tab)
  settings.rs, store.rs   the app's settings and its own files
  steam.rs                the sign-in and contract sync
  game.rs                 the TF2 watcher: running, matches, housekeeping, sync after TF2 closes
  maps.rs                 the map list, embedded from src/data/halloween-maps.json
  tf2/                    TF2's own files: the folder lookup, the process check, console.log, the casual queue,
                          items_game.txt (the contracts' end date)
  overlay/                the in-game overlay, shared by every widget
    mod.rs                the switches, the thread groups and what the Overlay tab reads
    run.rs                the overlay thread: follows TF2's window, draws the widgets, hotkeys
    window.rs, input.rs   the click-through windows, polled keys and mouse
    edit.rs, paint.rs     edit mode (moving, snapping, resizing), the drawing every widget shares
    settings.rs           radar.json: the switches, layout, hotkeys and the radar's RCON settings
    widgets/
      radar/              the gargoyle radar: RCON and demo threads, rcon.rs, demo.rs, nav.rs, panel.rs
      countdown.rs        the Scream Fortress countdown: its text and its panel
```

A widget owns its data and its drawing; `overlay/` places, shows and edits them. The overlay is Windows only and compiled out elsewhere.

## The data folder

It holds your Steam token, synced contracts, manual marks, the queue backup, the settings and the overlay settings (`radar.json`, named from before the overlay had other widgets). A debug build (`npm run tauri dev`) keeps it in the repo's `data` folder, created at runtime and ignored by git. Release builds use `%APPDATA%\tf2-halloween-utils` instead.
